# ADR 0009 — Agents talk over A2A; hand-offs are published findings

| | |
|---|---|
| Status | Accepted |
| Date | 2026-10-16 |

## Context

The staff's roles work together: the Doc hands the root cause of an incident to the Kiné, the Kiné reports a faulty version to the Mécano, the Coach asks the Nutri what keeping a margin would cost. The concept deck lists these "natural partners" for every role.

Two protocols could carry agent-to-agent exchanges:

- **MCP** is agent-to-tool: one request, one response. Turning an agent into another agent's "tool" loses task state, multi-turn exchanges and long-running work.
- **A2A** (Agent2Agent) is agent-to-agent: agent cards describing skills, tasks with a lifecycle (working, completed, input required), multi-turn, streaming and asynchronous work. Version 1.0 is the first stable specification, hosted by the Linux Foundation, with more than 150 supporting organizations (April 2026). agentgateway routes to A2A backends and attaches policies to them; kagent exposes every agent over A2A (ADR 0007); a Go SDK exists (`a2a-go`, spec 1.0).

## Decision

1. **Agents talk to each other over A2A**, always **through agentgateway**, never directly.
2. **Every TakeCare role exposes an A2A endpoint and an agent card** listing its skills (for the Doc: "diagnose an alert", "explain a past investigation"). With kagent, this is the agent's native endpoint; the card is generated by the operator from the role kind.
3. **Hand-offs are not conversations.** When a role passes a result to another (diagnosis → Kiné, faulty version → Mécano), it publishes a **finding**: a versioned Kubernetes resource (`TakeCareFinding`, to be specified with the first role that consumes it, milestone 3). Findings are deterministic, auditable, visible to humans and replayable. A2A is for **consultations**: an agent needs another's expertise while it works.
4. **Who may call whom is an allow-list**, enforced by the gateway. It is the "natural partners" table of the concept, turned into policy. An unlisted call is refused and traced.
5. **The level cannot be bypassed by delegation.** A task delegated over A2A runs with the **callee's** level and tools. A caller cannot make another agent do what the caller is not allowed to do: the gateway propagates the caller's identity and level, and a callee refuses a task that would require tools the caller's level does not allow.
6. **Every A2A call is traced** (ADR 0006): W3C trace context is propagated, so the Psy sees the whole chain.
7. **Budgets**: each role has a cap on A2A calls per task and on delegation depth (default 2), to prevent loops and runaway costs.

## Consequences

- Nothing to implement in milestone 1 (a single agent), but the Doc gets its A2A endpoint and agent card from day one, since the operator already talks to it over A2A (ADR 0007).
- The first agent-to-agent exchanges and the `TakeCareFinding` resource arrive with the Kiné (milestone 3).
- The gateway becomes the single control point for tools (MCP) and peers (A2A): the Ranger's ground.

## Rejected alternatives

- **Agents as MCP tools of each other**: works for one-shot questions, loses task lifecycle and multi-turn exchanges, and blurs the line between tools (governed by class) and peers (governed by partnership).
- **Free agent-to-agent conversation for every interaction**: costly, hard to audit, prone to loops; hand-offs belong in published findings.
